# 渡柜 / Dockroom · 跨服务器文件工作台

渡柜是用于可信局域网或 VPN 的 Windows 双栏文件传输工具。连接后，左栏浏览本机，右栏浏览远程主机，可在本地 NTFS 普通目录之间发送或下载单个文件，不覆盖同名文件。磁盘连接密钥允许访问主机当前 Windows 用户可读写的文件，只应交给可信设备。

### 从源码构建

安装 Go（版本见 `go.mod`）和 Node.js（版本见 `.node-version`），在 Windows PowerShell 中运行：

```powershell
npm --prefix web ci
.\scripts\build-windows.ps1
```

生成的程序为 `dist/Dockroom-Windows-x64.exe`。本项目使用 [MIT 许可证](LICENSE)。不要上传配对密钥、设备证书或本机状态目录。

### 原始设计记录（不代表已交付功能）

**一句话验收**：在左栏打开 Windows 制作机的 `D:\交付\十一月`，选中一个文件夹复制；右栏打开 Linux 归档机的 `/srv/archive/2026` 并粘贴。关闭网页后传输继续；重新登录能看到完成记录、目标真实路径和校验结果。反向复制走完全相同的操作。删除有明确归属，可从对应服务器的回收站恢复。

## 决策

做一个自托管网页应用。每台受管电脑安装一个 Agent，由它向 Hub 主动建立加密连接。每栏可独立切换服务器和目录，不固定哪边是源。文件由源 Agent 经 Hub 流到目标 Agent，不走操作员电脑，不在 Hub 建文件仓库。只管理管理员明确授权的目录，不开放整台机器。操作员的电脑如也要作为文件端，按同样方式装 Agent。

| 备选 | 适用情形 | 本项目取舍 |
|---|---|---|
| 桌面双栏 SFTP 客户端 | 少数已有 SSH 的机器，发起机常开 | Windows 未必有 SSH；操作电脑休眠影响任务 |
| 中枢挂载 SMB/NFS | 同一可信局域网，已有统一挂载和账号 | 不把跨网段共享、凭据与路径映射作为前置条件 |
| 双向同步软件 | 两个固定目录持续保持一致 | 这里要人工指定目标，不自动传播修改与删除 |
| 主动连接 Agent + 单 Hub | 能装服务，各机可出站访问中枢 | **选用**。代价是部署代理、中枢必须可信、带宽和可用性受中枢限制 |

基线假设：个人或小团队，2–20 台机器，一台常开的 Linux 中枢，有内网/VPN、可信 DNS 与证书。首发端点 Windows 10/11、Server 2019+ 与 Linux amd64；先验收本地 NTFS、ext4 上的专用共享目录。不能装代理的 NAS、只开放 SFTP 的托管服务器不宣称支持。无常开中枢或中枢不能读取内容，是需要重开架构决策的条件。

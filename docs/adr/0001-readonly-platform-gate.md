# ADR 0001 · 先验证端点语义，再接写 API

状态：接受（M0/M1 开发边界，不是减少发布范围）。原交付只有合同和离线样稿。当前执行机是 Windows/NTFS，未发现可运行的 Linux 端。

- Hub 保持 Go 单模块、SQLite/WAL、独立浏览器 HTTPS 与设备 mTLS/WSS；夹具 CA 可以给两个本地监听签服务器证书，浏览器仍验证链。
- Linux 只读用 `openat2`，无弱化回退；Windows 只支持盘符上的本地 NTFS，使用父句柄相对打开，拒绝 reparse、跨卷和特殊文件。根在本机确认身份，每次访问重新验证，拒绝物理重叠或内部区。
- Linux M1 暂不穿越配置路径上的挂载边界（包括 bind mount），故只有与 `/` 同一挂载的专用根可参与只读候选验收。独立 ext4 数据卷需实机核对合法卷入口与挂载别名后再解禁。
- M0 的独占发布/回收/恢复仅为合成根试验，不连接 Agent 写命令。M1 即使配置读写也只发布 `readOnly` 能力；替代验收为独立 Hub 与两个 Windows Agent。Linux 交叉构建/契约夹具不算 ext4 签收。
- 无 Windows 服务/ACL 安装器及自动证书轮换；开发启动器仅用于隔离回环夹具，M4 另验低权限账户、ACL、轮换和灾备。
- 写 API 须证明专用根/私有区、落盘水位、intent/receipt 和重启对账。单次独占重命名成功不开放写根。

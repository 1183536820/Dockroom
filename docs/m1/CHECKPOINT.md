# M1 · 双节点只读纵向切片

结论：Windows/NTFS 上的独立 Hub + 两个独立 Agent 只读切片可复现。不是 Windows + Linux 实机签收；Linux amd64 Hub、Agent、文件系统测试仅交叉构建。启动见 [M1 手册](../START-M1.md)。

| 验收 | 结果 |
|---|---|
| A01（Windows 双进程部分） | 通过：两栏互换、独立历史、原生路径定位及复制、200+7 分页、跨整目录筛选、空目录、停止/重连、恢复已授权位置；Linux 路径为 schema 夹具，Linux 真实浏览待验 |
| A10（本阶段只读部分） | 通过：根外 junction / 跳转 / 保留区拒绝，越权用户不见节点/根；同根另一用户不能复用分页游标；撤销读取和证书后请求失败；旧 rootId 不继承新物理目录的读取授权；无会话和错误 Origin/CSRF 拦截。M2–M3 写入边界另验 |
| A12（局部） | 通过：装配全新本地 Hub，TLS/mTLS、一次性接入/指纹核对、节点撤销；Hub 进程重启后配对、会话与授权可用；不代表安装包、升级或备份演练已通过 |
| A02–A09 中未有的写链路；A11、A13 | 未通过整项验收：当前没有复制、回收、变更或任务 API |

证据：Chrome Playwright 的独立进程测试及运行摘要；1440、1024、390 CSS px 与断开一端的真实界面图片（见 `evidence/`）。已用 Enter 打开实体目录，未验收全程键盘复制。Go 竞态检查未跑：当前环境无 Go 所需 cgo 工具链。未以 loopback 推算 LAN 性能。

保留边界：浏览接口只允许现行 root grant；根身份每次操作复核，文件名当文本展示，无脚本或字节中转接口。配置读写根也只返回实际只读能力。暂不支持 Linux 挂载边界上的授权根，见 ADR 0001。

# M2 · Windows/NTFS 单文件复制切片通过

按 [ADR 0002](../adr/0002-windows-first.md) 验收：一个 Windows 宿主上，独立的 TLS Hub 与两个 NTFS Agent 进程。不是两个物理主机或生产部署。Linux amd64 交叉构建通过，当前只读，实机不作本阶段门槛。

| 出口 | Windows NTFS 隔离实测 |
|---|---|
| 读根→可写根，A→B→A | PASS：8,388,765 字节跨 8 MiB 分片，前后 SHA-256 一致、源未变，mtime 一致；另测空文件 |
| 浏览器不参与执行 | PASS：选择文件并复制引用，切换源目录，向另一栏粘贴、确认；关标签页，重开看完成、目标路径、目标 SHA-256 并定位目标 |
| 断线、进程重启、ACK 丢失 | PASS：目标累计持久写入 8 MiB 后杀 Agent 与重启 Hub；另一次在 NTFS 发布后、写 receipt 前杀 Agent 并重启 Hub，核对原目标后仅出现一份 |
| 同名、幂等、授权与取消 | PASS：双击等价确认同一个任务；既有/预检后新出现的同名文件不覆盖；源变更拒绝；只读目标拒绝；传输中的取消/撤权不发布；其他账号不可见任务 |

设备控制不传文件字节；数据流用 mTLS 短票据握手。HTTP 204 只代表中继阶段，不代表文件成功。端点校验、同卷独占发布、持久台账和实体核对后才显示完成。

复现见 [Windows 试运行](../START-WINDOWS.md)，证据见 [运行摘要](evidence/run-summary.md)、[复制确认](evidence/m2-confirm.png)、[完成校验](evidence/m2-verified.png)。本轮仍未覆盖多选、目录、保留两份、软删除、恢复、人工重试、生产 ACL/服务和物理掉电。端点私有区暂时不自动清理；生产部署不可用此夹具手册替代。

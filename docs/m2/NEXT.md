# M2 · 下一条可验证接线

只在专用夹具执行。不要因为测试中继已经能收完数据，就把复制标为成功。

1. 端点：从已授权根句柄打开源文件；将 `version` 与同一打开对象绑定，分片读前/后及发布前复查。目标在固定同卷私有区内按稳定 ID 取句柄，写探测必须证明专用低权限账户、ACL 和写入场景；对无法证明的平台/卷保持只读。
2. Hub：将单文件的 plan/消费幂等键、job/item 状态与租约持久化。每个 handler 核对当前 grant，先确认目标 `GET` 已就绪，再发源 `PUT`。只有端点校验且提交持久 ACK 才推进；控制与有效载荷分开。Hub 重启先对账，不自动重复发布。
3. 端点：把 `journal` 的确认前缀接到断线重试；重读源和暂存做完整 SHA-256。准备 intent，使用与 M0 同等的基于句柄独占发布；同步可用元数据，使用固定父句柄和对象身份辨别 intent，再向 Hub 回报 receipt。
4. 门槛：独立进程 A→B→A，至少一个样本跨 8 MiB 边界。保存两端原始/最终哈希；关闭浏览器不阻塞，断 ACK/重启/撤权/取消均不得显示错误完成，不覆盖预置目标，不盲目重放。通过后再进入目录、多选、回收维护。
